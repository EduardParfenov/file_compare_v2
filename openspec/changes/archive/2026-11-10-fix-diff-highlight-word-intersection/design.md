## Context

В `static/app.js` функция `applyDiffToPanel` вызывает `buildDiffWordsHtml`, которая вызывает `mapWordsToOps` для каждой страницы отдельно. `mapWordsToOps` сбрасывает `blockIdx = 0` в начале каждой страницы, что неэффективно и противоречит документированному намерению «без сброса на каждой странице». Кроме того, если бы предлагался фрагмент с полями `globalStart`/`globalEnd`, он не совпадал бы с реальными именами полей бэкенда (`global_char_start`/`global_char_end`/`word`), что сделало бы пересечение диапазонов нерабочим. Функции `insertDiffSpacers` и `syncScroll` полагаются на CSS-классы `.diff-word.delete` / `.diff-word.insert`, поэтому любая перерисовка diff-слоя должна гарантированно оставлять эти классы.

## Goals / Non-Goals

**Goals:**
- Исправить маппинг слов на операции diff (`EQUAL`/`DELETE`/`INSERT`) так, чтобы подсветка загоралась корректно на всех страницах.
- Использовать реальные имена полей бэкенда: `global_char_start`, `global_char_end`, `word`.
- Сделать `blockIdx` сквозным итератором по глобальному массиву блоков `diffResult` без сброса в `0` на каждой странице.
- Сохранить CSS-классы `.diff-word.delete`, `.diff-word.insert`, `.diff-word.equal` для совместимости с `insertDiffSpacers` и видимости текста EQUAL.
- Удалить мёртвый код, ставшие избыточным после рефакторинга.

**Non-Goals:**
- Изменение формата ответа API `/api/v1/compare`.
- Изменение алгоритма diff (diff-match-patch остаётся без изменений).
- Изменение логики скроллинга, спейсеров или ИИ-функций.

## Decisions

**Перенос `blockIdx` между страницами.**
- Решение: `applyDiffToPanel` сам управляет `blockIdx` как сквозным итератором по всем страницам панели, передавая его в функцию маппинга по ссылке/возвращая обновлённое значение.
- Обоснование: убирает неэффективный `while`-пропуск блоков на каждой странице и соответствует намерению, зафиксированному в комментарии кода.
- Альтернатива: оставить сброс `blockIdx = 0` на каждой странице (текущее поведение) — отвергнуто, так как неэффективно и противоречит документации.

**Использование существующей функции `mapWordsToOps` вместо инлайнового цикла.**
- Решение: отрефакторить `mapWordsToOps`, чтобы она принимала и возвращала `blockIdx`, и вызывалась из `applyDiffToPanel` с переносом индекса между страницами.
- Обоснование: минимизирует изменения, не вводит новый инлайновый цикл, сохраняет разделение ответственности (маппинг vs отрисовка).
- Альтернатива: заменить на инлайновый цикл пересечения диапазонов (как в предлагаемом фрагменте) — отвергнуто, так как сломает `insertDiffSpacers` (отсутствие CSS-классов `delete`/`insert`) и сделает EQUAL-текст прозрачным (`text-transparent`).

**Сохранение классов `.delete` / `.insert` / `.equal` из `styles.css`.**
- Решение: генерируемые `<span>` получают класс `diff-word delete` / `diff-word insert` / `diff-word equal` через существующие CSS-классы.
- Обоснование: `insertDiffSpacers` ищет `.diff-word.delete` / `.diff-word.insert`; EQUAL-текст остаётся видимым через `.diff-word.equal { color: #111827 }`.

**Удаление `buildDiffWordsHtml`.**
- Решение: после переноса логики маппинга в `applyDiffToPanel` с сквозным `blockIdx` функция `buildDiffWordsHtml` становится избыточной и удаляется.
- Обоснование: убрать мёртвый код, снизить уровень вложенности.

## Risks / Trade-offs

- [Сложность отслеживания `blockIdx` между страницами] → если порядок страниц в DOM не совпадает с порядком блоков в `diffResult`, маппинг может сломаться. Однако `page_number` и глобальные индексы гарантируют корректный порядок.
- [Регрессия подсветки на больших документах] → линейный проход с двумя указателями остаётся O(N+M), приемлемо для типичных PDF.
- [Зависимость `insertDiffSpacers` от CSS-классов] → если классы `delete`/`insert` исчезнут, спейсеры перестанут вставляться. Сохранение классов устраняет этот риск.

## Migration Plan

- Обновить `static/app.js`: переработать `applyDiffToPanel` и `mapWordsToOps` со сквозным `blockIdx`, сохранить CSS-классы.
- Удалить `buildDiffWordsHtml` как избыточную.
- Добавить тесты в `tests/` для маппинга слов на операции diff.
- Проверить `pytest` и визуально проверить подсветку на тестовом PDF.
