## Context

См. `proposal.md` — Why. Ниже — только техническое состояние, которое определяет подход.

Наблюдаемое сегодня поведение (проверено в headless Chromium на текущем коде, приложение поднято локально, окно 1280×800):

- `static/index.html:63` — у шапки боковой панели ИИ стоит inline-обработчик `onclick="toggleAiPanel()"`. `static/app.js` подключается как ES-модуль (`<script type="module">` в `index.html:99-102`, `export function initApp`), поэтому `toggleAiPanel` существует в модульной области видимости и недоступен как `window.toggleAiPanel`. Клик по шапке даёт `pageerror: toggleAiPanel is not defined`; состояние панели не меняется.
- `static/app.js::consumeSseStream` — единственное место чтения SSE-потока; `onChunk` вызывается для каждого кадра данных, но число полученных фрагментов нигде не фиксируется. `runAiAnalysis` и `generateAiPageReport` очищают `#aiOutput` (`textContent = ""`) перед запуском. Поэтому «успешный, но пустой» ответ (бэкенд корректно отдаёт HTTP 200 без единого кадра данных — `main.py::_open_sse_stream` возвращает `first = None` при `StopAsyncIteration`) оставляет область вывода пустой и без пояснения.
- `static/index.html:18` — `body` имеет класс `h-screen overflow-hidden`, но не является flex-контейнером; `main` (строка 39) имеет класс `h-full`, то есть `height: 100%` от высоты `body` (800 px), независимо от высоты `header` (65 px). Измерено: `body.scrollHeight` = 865 при `body.clientHeight` = 800, `main` = 800 px, нижняя граница боковой панели ИИ — 865 px. `overflow: hidden` срезает нижние 65 px: кнопка «Сгенерировать ИИ-отчёт по странице» и часть области вывода ИИ недоступны.
- `tests/test_frontend_upload.py:167` уже проверяет `js_errors == []`, но клик по шапке панели не выполняет — поэтому первый дефект не ловится.
- Браузерный харнесс (`_free_port`, `_chromium_installed`, фикстуры `pdf_files`, `live_server`, `browser_page`) продублирован дословно в `tests/test_frontend_upload.py` и `tests/test_frontend_ai_stream_error.py`.

Проверенные факты, определяющие решения:

- Элемент с inline-атрибутом `onclick` разрешает имя в глобальной области видимости документа; имя из модульной области видимости ES-модуля в неё не попадает.
- Flex-элемент по умолчанию имеет `min-height: auto`, то есть не сжимается ниже собственной высоты содержимого — без явного `min-height: 0` колонка с прокручиваемым содержимым продолжает распирать контейнер.
- В flex-контейнере с `flex-direction: column` `flex-basis: 0%` (`flex-1`) задаёт базовый размер флекс-элемента, и `height: 100%` на нём не влияет на итоговую высоту.
- Класс Tailwind `min-h-0` равен `min-height: 0px`; `shrink-0` равен `flex-shrink: 0`.

Проверка правки раскладки выполнена без изменения репозитория — через инъекцию классов в браузере: `body` получает `flex flex-col`, `header` — `shrink-0`, у `main` убирается `h-full` и добавляется `min-h-0`. Результат: `body.scrollHeight` = 800 при `clientHeight` = 800, `main` = 735 px, нижняя граница боковой панели ИИ — 800 px (то есть видна полностью), вертикальная прокрутка страницы отсутствует; при окне 1024×700 — `body.scrollHeight` = 700.

## Goals / Non-Goals

**Goals:**

- Шапка панели ИИ-аналитики действительно переключает её видимость, и ни один пользовательский клик не порождает ошибку JavaScript.
- Пустой успешный ответ ИИ-модели получает явное пояснение, отдельное от вывода модели и от сообщения об ошибке.
- Интерфейс занимает высоту окна целиком: ничего не срезано, страница не прокручивается, панели прокручиваются внутри себя.
- Браузерный харнесс существует в одном месте и переиспользуется новыми тестами.

**Non-Goals:**

- Геометрия diff-оверлея и модель масштаба (бэклог P0.3), lockstep-синхронизация и спейсеры (P0.4) — отдельные change'ы, в этом scope не затрагиваются.
- Контекст для ИИ-анализа (P0.5): состав и формат запроса к модели не меняются.
- Валидация загрузок и очистка временных файлов (P1.2), вынос блокирующих операций из event loop (P1.1), сброс состояния между сравнениями (P1.4) — бэкенд не затрагивается.
- Приведение кода к стилю `ruff format` и разбиение длинных функций (P2.15) — отдельный chore-change.
- Регрессионный тест на совпадение подсветки со словами на странице: он падал бы до исправления P0.3 (измеренное расхождение — 148 px при ширине canvas 447 px против ширины слоя 595 px) и зафиксирован как входные данные будущего change'а по P0.3.

## Decisions

### D1. Переключатель панели — подписка на событие вместо inline-обработчика

Inline-атрибут `onclick` в `static/index.html` удаляется; шапке панели даётся идентификатор, а обработчик регистрируется в `static/app.js` внутри `initApp()` через `addEventListener("click", ...)`. Сама функция переключения остаётся модульной и не публикуется в `window`.

- **Почему:** модуль остаётся самодостаточным — ни один его обработчик не зависит от того, как страница его подключила. Это устраняет целый класс дефектов того же рода (обработчик виден в разметке, но недоступен из модуля) и не требует «экспортировать всё в `window`».
- **Альтернатива A (отклонена):** добавить в `static/app.js` строку `window.toggleAiPanel = toggleAiPanel`. Работает, но сохраняет глобальную зависимость и оставляет inline-атрибут в разметке — то есть сохраняет исходную причину дефекта, просто маскируя её.
- **Альтернатива B (отклонена):** оставить inline-атрибут и подключить `static/app.js` обычным скриптом (не модулем), чтобы функции попали в глобальную область. Отклонено: теряется модульность `app.js` (экспорт `initApp` используется в `index.html`), и появляется ещё одна зависимость от порядка загрузки скриптов.
- Подписка вешается на саму шапку (а не только на стрелку `#aiPanelToggle`), чтобы нажатие по заголовку «🤖 AI Аналитика» тоже переключало панель — как это было задумано до дефекта.

### D2. Пустой ответ определяется по счётчику фрагментов, возвращаемому разбором потока

`consumeSseStream(response, { onChunk, onError })` начинает возвращать объект-итог `{ chunkCount, errorShown }`: `chunkCount` увеличивается на каждый кадр данных, `errorShown` уже отслеживается внутри функции для защиты от повторного показа ошибки. Оба вызова (`runAiAnalysis`, `generateAiPageReport`) после завершения разбора проверяют: `chunkCount === 0 && !errorShown` → показать пояснение о пустом ответе.

- **Почему:** единственное место, где известно, пришёл ли хоть один кадр, — разбор потока; возвращаемый итог избавляет от дублирования счётчика в двух вызывающих местах и делает признак «пусто» проверяемым в одном месте.
- **Альтернатива A (отклонена):** завести отдельный колбэк `onEmpty` в `consumeSseStream`. Работает, но добавляет третий обработчик в контракт функции ради случая, который вызывающий код и так может вычислить из возвращаемого итога.
- **Альтернатива B (отклонена):** определять пустой ответ на стороне сервера — например, отдавать отдельный SSE-кадр «конец без содержимого». Это меняет контракт потока и требует правок на обеих сторонах ради ситуации, которую фронтенд и так распознаёт однозначно (ноль кадров данных, ошибки нет).

### D3. Пояснение о пустом ответе — отдельный блок, а не текст в области вывода

В `static/index.html` добавляется элемент `#aiEmpty` рядом с `#aiError`, изначально скрытый тем же механизмом `ui-hidden` (`display: none !important`, `static/styles.css:88`). Управление видимостью — через `showAiEmptyAnswer()` / `hideAiEmptyAnswer()` в `static/app.js`, симметрично существующим `showAiError()` / `hideAiError()`.

- **Почему отдельный элемент:** `#aiOutput` — область потокового вывода модели; служебная реплика системы в ней была бы неотличима от текста модели, а при очистке области перед следующим запуском исчезла бы вместе с выводом. Отдельный блок сохраняет разделение «вывод модели» / «сообщение системы» и повторяет уже принятый в проекте паттерн `#aiError`.
- Оформление — нейтральное (серый текст на тёмном фоне), а не красное: пустой ответ не является ошибкой.
- Перед каждым запуском анализа блок скрывается, как это уже делается для `#aiError`, чтобы устаревшее пояснение не оставалось на экране.

### D4. Раскладка: `body` — flex-колонка, `main` — `flex-1 min-h-0` без `h-full`

Правка в `static/index.html` (классы Tailwind, без новых правил в `static/styles.css`):

- `body`: добавить `flex flex-col` (шапка и основная область становятся элементами вертикальной колонки).
- `header`: добавить `shrink-0` (шапка не сжимается).
- `main`: убрать `h-full`, добавить `min-h-0`.

- **Почему:** в flex-колонке `flex-1` задаёт `flex-basis: 0%`, поэтому `main` занимает ровно оставшуюся после шапки высоту; `min-h-0` снимает поведение `min-height: auto`, из-за которого прокручиваемое содержимое распирало бы колонку обратно.
- **Почему убрать `h-full`, а не перебить его:** `height: 100%` на флекс-элементе в колонке конфликтует с расчётом по `flex-basis`; удаление класса устраняет конфликт, а не маскирует его.
- **Альтернатива A (отклонена):** оставить `body` блочным и включить вертикальную прокрутку страницы (`overflow-y: auto`). Тогда страница и панели прокручиваются одновременно, а колесо мыши над панелью страниц прокручивает всё окно — для сравнения документов это разрушительно.
- **Альтернатива B (отклонена):** задать фиксированные размеры в пикселях (`h-[735px]`). Не переживает изменение высоты окна и ломается при появлении полосы прокрутки в шапке.
- `main` сохраняет собственный `display: flex` (Tailwind-класс `flex`) — это его внутренняя раскладка в строку (две панели сравнения и боковая панель ИИ) и она не конфликтует с ролью флекс-элемента колонки `body`.

### D5. Общий браузерный харнесс переносится в `tests/conftest.py`

Дублирующиеся части (`_free_port`, `_chromium_installed`, фикстуры `pdf_files`, `live_server`, `browser_page`) переносятся в `tests/conftest.py`; оба существующих браузерных тестовых файла используют общие фикстуры.

- Разделение областей видимости: `live_server` — **session scope** (один поднятый uvicorn на всю сессию тестов), `chromium_browser` и `browser_page` — **module scope** (свежий браузер, свежая страница и свежий список `js_errors` на каждый модуль).
- **Почему `browser_page` остаётся module scope:** список накопленных JS-ошибок сейчас изолирован между модулями, и `tests/test_frontend_upload.py` проверяет `js_errors == []`. При session scope эта проверка захватила бы ошибки из чужих модулей — появилось бы ложное (или, наоборот, скрытое) взаимодействие между тестами.
- **Почему браузер — module scope, а не session scope:** открытый контекст `sync_playwright()` держит в главном потоке работающий event loop asyncio. Проверено измерением: внутри контекста `asyncio.run()` падает с `RuntimeError: asyncio.run() cannot be called from a running event loop`, после выхода из контекста — работает. На сессионной области контекст оставался бы открытым во время небраузерных тестов, и `tests/test_streaming_errors.py` (использует `asyncio.run()`) начал бы падать этим `RuntimeError` вместо проверяемого результата. Поэтому контекст Playwright закрывается вместе с модулем; цена — по одному запуску браузера на браузерный модуль, как и до переноса.
- **Почему `live_server` безопасен на сессионной области:** uvicorn работает в отдельном потоке со своим event loop, а работающий цикл — потоковая переменная asyncio, поэтому главный поток тестов он не затрагивает.
- **Почему проверка браузера переносится внутрь фикстуры, а не остаётся `pytestmark`:** `pytestmark` в `conftest.py` применился бы ко всем тестам набора, включая небраузерные. Пропуск выполняется внутри фикстуры (`pytest.skip`), поэтому страдают только тесты, которым реально нужен браузер, а импорт `conftest.py` не тянет запуск браузера.
- Набор тестовых PDF становится общим: одна пара документов (исходная версия и версия с удалённым и добавленным абзацем) используется всеми браузерными тестами — это даёт одинаковый дифф во всех сценариях.

### D6. Тесты

Новый файл `tests/test_frontend_ui_layout.py` (Playwright, на общих фикстурах):

- **Переключатель панели:** клик по шапке → `#aiPanelContent` получает класс `ui-hidden`, индикатор `#aiPanelToggle` меняет символ; повторный клик → панель снова видна; `js_errors` пуст.
- **Пустой ответ модели:** `main.vllm_client` подменяется клиентом, чей `stream_analysis` — async-генератор, завершающийся без единого `yield` (по образцу существующего `_FailingMidStreamClient`); после запуска анализа `#aiEmpty` видим и содержит пояснение; `#aiError` при этом скрыт.
- **Раскладка:** `document.body.scrollHeight <= window.innerHeight`; нижняя граница боковой панели ИИ не выходит за пределы окна; при изменении высоты окна (1280×800 → 1024×700) те же условия выполняются.

Существующие браузерные тесты переводятся на общие фикстуры без изменения набора проверок.

- **Проверка регрессионной ценности:** до исправления новые тесты обязаны падать — переключатель даёт `pageerror`, пустой ответ не показывает пояснение, раскладка даёт `body.scrollHeight` = 865 при высоте окна 800. Это фиксируется в задачах приёмки.
- **Альтернатива (отклонена):** переносить логику фронтенда в Python-порт и тестировать порт. Такой подход в бэклоге (P1.5) уже помечен как ложнозелёный: он проверяет копию логики, а не `static/app.js`.

### D7. Границы изменения

- Изменение целиком во фронтенде: `static/index.html`, `static/app.js`, `static/styles.css` (последний — только если потребуется оформление `#aiEmpty`; базовые стили `ui-hidden` уже есть).
- Бэкенд, маршруты API, формат SSE-кадров и структура запросов к модели не меняются: «успешный пустой» ответ уже отдаётся корректно, его достаточно корректно распознать на клиенте.
- `AGENTS.md` и `README.md` правок не требуют: перечисленный в `AGENTS.md` §14 публичный API не меняется, а README не описывает ни поведение переключателя, ни раскладку.

## Risks / Trade-offs

- [Существующий браузерный тест завязан на текущие размеры панели] → после правки раскладки высота области страниц уменьшается (при окне 1280×720 — с 655 до 655 px области страниц при высоте `main` 655 вместо 720); существующие проверки касаются статуса и JS-ошибок, а не абсолютных размеров, поэтому должны остаться зелёными — проверяется прогоном набора.
- [Перенос фикстур в `conftest.py` затрагивает два существующих тестовых файла] → риск локализован выносом без изменения логики проверок; факт подтверждается зелёным прогоном всего набора.
- [Сессионный `live_server` живёт дольше отдельных модулей] → сервер поднимается один раз и останавливается по завершении сессии; состояние между модулями не используется, подмена `main.vllm_client` через `monkeypatch` откатывается после каждого теста.
- [Открытый контекст Playwright оставляет работающий event loop asyncio в главном потоке] → контекст закрывается вместе с модулем (`chromium_browser` — module scope), поэтому небраузерные тесты, использующие `asyncio.run()`, не ломаются. Проверено измерением: внутри контекста `asyncio.run()` падает, после выхода — работает.
- [Проверка наличия Chromium выполняется при первом обращении к фикстуре и требует запуска браузера] → выполняется один раз на сессию; при отсутствии Chromium тесты пропускаются с понятным сообщением, а не падают.
- [Пояснение о пустом ответе может быть показано вместе с ошибкой при гонке] → условие показа требует отсутствия ошибки (`!errorShown`), а блок ошибки очищается перед каждым запуском; взаимное исключение закреплено сценарием спецификации.
- [Правка раскладки меняет геометрию и может повлиять на будущий переход на fit-to-width (P0.3)] → правка задаёт корректную базовую раскладку (область страниц занимает оставшуюся высоту), а не масштаб содержимого; вопрос масштаба решается в отдельном change'е и на эту правку не влияет.

## Migration Plan

1. Изменение атомарно: фронтенд и тесты меняются в одном pull request, порядок выкладки не важен (серверные маршруты и формат потока не меняются).
2. Откат: revert pull request; миграция данных не требуется, состояние на диске не меняется.

## Open Questions

- Нужен ли отдельный визуальный акцент для пояснения о пустом ответе (например, предупреждающий тон вместо нейтрального) — нет: пустой ответ не является ошибкой, и нейтральное оформление не путает его с блоком `#aiError`. Вопрос снимается в рамках этого change'а.
- Следует ли показывать пояснение о пустом ответе при ошибке потока, если до обрыва не пришло ни одного фрагмента — нет: пользователю нужна причина сбоя, а она уже показана в `#aiError`. Закреплено сценарием спецификации.
