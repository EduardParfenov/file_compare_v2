## Why

При сравнении многостраничных PDF подсветка diff «съезжает» на страницах после первой: diff_engine.py не привязывает блоки diff к глобальным символьным смещениям, а фронтенд пытается сопоставить локальные слова страницы с глобальными блоками вручную. Кроме того, скроллинг панелей работает по пропорции пикселей, а не по текстовым якорям, поэтому при вставках/удалении строк разъезжаются. Из-за этого визуальное сравнение теряет смысл на всех страницах, кроме первой.

## What Changes

- В `services/diff_engine.py` добавить поля `char_start` и `char_end` в `DiffBlock` и вычислять сквозные символьные смещения для каждого блока в обеих панелях (EQUAL, DELETE, INSERT), чтобы фронтенд мог сопоставлять блоки diff со словами без ручного накопления смещений.
- В `static/app.js` переписать `mapWordsToOps`: использовать `char_start`/`char_end` блоков напрямую вместо ручного перебора с накоплением `block.text.length`, устранив зависимость от порядка и сброса указателя между страницами.
- В `static/app.js` заменить `syncScroll` (пропорция пикселей) на синхронизацию, привязанную к текстовым якорям (блокам): при прокрутке через блок INSERT/DELETE противоположное окно «замирает» (показывает спейсер) до тех пор, пока вторая панель не пройдёт изменённый фрагмент.
- Сохранить существующий внешний контракт API `/api/v1/compare` без изменений.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `pdf-hybrid-comparison`: уточняются требования — блоки diff (`left_panel.blocks` / `right_panel.blocks`) SHALL нести сквозные символьные индексы `char_start` / `char_end`, а синхронный скроллинг SHALL быть привязан к текстовым якорям (блокам), а не к сырым пикселям. Требуется дельта-спецификация этих требований.

## Impact

- `services/diff_engine.py` — `DiffBlock` дополняется полями `char_start` / `char_end`; `compute_diff` вычисляет их для всех блоков.
- `static/app.js` — `mapWordsToOps` упрощается и надёжнее; `syncScroll` заменяется на якорную синхронизацию.
- Внешний контракт API не меняется; `services/pdf_handler.py` и `services/vllm_client.py` без изменений.
