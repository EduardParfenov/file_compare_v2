## MODIFIED Requirements

### Requirement: Команда запуска тестов не зависит от рабочего каталога

Тесты SHALL собираться и выполняться командой `pytest` из корня репозитория, а из любого другого рабочего каталога — той же командой с указанием пути к каталогу тестов, без ручной установки путей и без зависимости от того, откуда запущена команда.

#### Scenario: Запуск из корня репозитория

- **WHEN** выполняется команда `pytest` из корня репозитория
- **THEN** собираются и выполняются все тесты проекта без ошибки импорта

#### Scenario: Запуск из произвольного каталога

- **WHEN** выполняется команда `pytest` с указанием пути к каталогу тестов из каталога, отличного от корня репозитория
- **THEN** собираются и выполняются те же тесты проекта, что и при запуске из корня репозитория, без ошибки импорта

#### Scenario: Запуск из подкаталога проекта без указания путей

- **WHEN** выполняется команда `pytest` без указания путей из подкаталога корня репозитория
- **THEN** тесты не собираются, а команда завершается кодом «тесты не найдены», а не ошибкой сбора или ошибкой импорта

#### Scenario: Сбор ограничена каталогом тестов

- **WHEN** выполняется команда `pytest` из корня репозитория без указания путей
- **THEN** собираются только тесты проекта, а не содержимое виртуального окружения и других служебных каталогов

## ADDED Requirements

### Requirement: Основная ветка защищена правилом репозитория

Репозиторий SHALL содержать активное правило защиты основной ветки, которое запрещает изменение основной ветки в обход pull request, не допускает обхода правила владельцем репозитория и требует успешного прохождения обязательной проверки перед слиянием.

#### Scenario: Изменение попадает в основную ветку

- **WHEN** изменения попадают в основную ветку
- **THEN** это происходит только через pull request, в котором обязательная проверка завершилась успешно

#### Scenario: Попытка прямого push

- **WHEN** выполняется прямой push в основную ветку, в том числе владельцем репозитория
- **THEN** push отклоняется сервером, а правило не имеет списка обхода

#### Scenario: Обязательная проверка не пройдена

- **WHEN** в pull request обязательная проверка завершилась с ошибкой или ещё не запустилась
- **THEN** слияние pull request недоступно

#### Scenario: Описание правила в документации

- **WHEN** состояние правила защиты основной ветки описывается в документации проекта
- **THEN** описание соответствует фактическим настройкам репозитория и не утверждает, что защита действует, если она отключена

### Requirement: Имя обязательной проверки совпадает с job в CI

Имя проверки, выбранной обязательной в правиле защиты основной ветки, SHALL совпадать с именем job в CI, который выполняет набор тестов.

#### Scenario: Обязательная проверка привязана к существующему job

- **WHEN** правило защиты основной ветки требует проверку
- **THEN** в pull request отображается проверка с этим именем, и её результат определяет возможность слияния

#### Scenario: Job в CI переименован

- **WHEN** имя job в CI изменено без обновления правила защиты основной ветки
- **THEN** обязательная проверка не находится в pull request, и слияние остаётся заблокированным до синхронизации имени в правиле репозитория
