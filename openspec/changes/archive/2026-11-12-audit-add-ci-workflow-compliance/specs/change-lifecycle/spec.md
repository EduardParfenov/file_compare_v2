## Purpose

Задаёт единый порядок работы с change'ами в проекте: как подтверждается приёмка, когда выполняется архивирование и куда записываются факты о состоянии репозитория, чтобы архив оставался достоверным источником истории и правила проекта можно было соблюдать без устных договорённостей.

## ADDED Requirements

### Requirement: Приёмка change'а подтверждается фактами до архивирования

Задачи приёмки в чек-листе change'а SHALL закрываться только при наличии проверяемого факта — идентификатора pull request, вывода команды или ссылки на прогон проверки — и этот факт SHALL быть зафиксирован до переноса change'а в архив.

#### Scenario: Задача приёмки без факта

- **WHEN** задача приёмки отмечена выполненной, но проверяемый факт не зафиксирован
- **THEN** задача не считается закрытой, и change не переносится в архив

#### Scenario: Факт приёмки ссылается на pull request

- **WHEN** в задаче приёмки указан факт со ссылкой на pull request
- **THEN** в этом pull request виден результат автоматической проверки, соответствующий указанному факту

### Requirement: Архивирование change'а выполняется в составе pull request

Change SHALL переноситься в архив в составе pull request, который его содержит, и только после того как задачи приёмки подтверждены проверяемыми фактами; задачи приёмки, требующие подтверждения на стороне GitHub, SHALL закрываться в том же pull request по факту успешной проверки.

#### Scenario: Приёмка не подтверждена

- **WHEN** задачи приёмки change'а ещё не подтверждены фактами
- **THEN** change остаётся активным и не переносится в архив

#### Scenario: Change архивируется в составе pull request

- **WHEN** приёмка подтверждена фактами и pull request с change'ом создан
- **THEN** change переносится в архив, и задачи приёмки, требующие подтверждения на стороне GitHub, закрываются в этом же pull request по факту успешной проверки

#### Scenario: Порядок операций противоречив в артефактах

- **WHEN** артефакты change'а (план реализации и чек-лист) описывают разный порядок архивирования
- **THEN** противоречие устраняется до архивирования, и канонический порядок фиксируется в правилах проекта

### Requirement: Архивные артефакты не переписываются задним числом

Артефакты change'а, перенесённого в архив, SHALL не дополняться новыми фактами после архивирования; исправление фактического противоречия в архивном артефакте SHALL помечаться как датированное уточнение с указанием причины.

#### Scenario: Новый факт о состоянии репозитория

- **WHEN** после архивирования появляется новый факт, например настройка правила защиты ветки на стороне GitHub
- **THEN** факт фиксируется в документации проекта и в главных спецификациях, а архивный артефакт не дополняется

#### Scenario: Ошибка в архивном артефакте

- **WHEN** в архивном артефакте обнаружено фактическое противоречие
- **THEN** артефакт исправляется с датированной пометкой об уточнении и указанием причины исправления

### Requirement: Изменения состояния репозитория фиксируются в репозитории

Факты о состоянии репозитория и о правилах, действующих на стороне GitHub, SHALL отражаться в документации проекта и попадать в репозиторий через отдельную ветку и pull request.

#### Scenario: Правило защиты ветки настроено

- **WHEN** владелец настраивает правило защиты основной ветки на стороне GitHub
- **THEN** документация проекта описывает это правило, а соответствующая правка попадает в репозиторий через pull request

#### Scenario: Правка документации осталась в рабочем дереве

- **WHEN** правка документации не закоммичена
- **THEN** она не считается принятой: она не защищена правилом защиты основной ветки и может быть потеряна

### Requirement: Канонический порядок операций зафиксирован в правилах проекта

Правила проекта SHALL содержать единый порядок операций над change'ом (планирование → реализация → приёмка → pull request → подтверждение приёмки фактами → закрытие задач приёмки и архивирование change'а в том же pull request → слияние) и правило неизменяемости архивных артефактов.

#### Scenario: Агент приступает к работе с change'ом

- **WHEN** агент начинает работу над change'ом
- **THEN** в правилах проекта указано, в каком порядке выполняются приёмка, слияние и архивирование, и какие действия требуют явного разрешения пользователя
