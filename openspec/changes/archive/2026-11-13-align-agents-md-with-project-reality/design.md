## Context

See `proposal.md` — Why (мотивация) и `specs/agent-governance/spec.md` (контракт требований).

Текущее состояние, важное для подхода:

- `AGENTS.md` переписан пользователем в новую структуру (TL;DR из 12 правил, разделы с эмодзи, §4 «Приватные данные», §8 «Правила взаимодействия с агентом», §11 «Definition of Done», §14 «Ключевые API»). Структура новая и удачная — сохраняем её; правим только фактические ошибки и пробелы.
- Фактические ошибки новой редакции (проверено по коду): несуществующий `services/ai_context.py`; несуществующий `VllmClient.stream_chat()` (фактически — `stream_analysis()` и `stream_analysis_with_image()`); конфиг линтера указан как `pyproject.toml` (фактически `ruff.toml`, `pyproject.toml` в репозитории нет); несуществующее поле `settings.output_dir`; несуществующий тип `TextBlock` в примерах; `extract_text_and_coords` в примере имеет сигнатуру `(Path) -> list[TextBlock]`, фактически — `(str) -> dict`; пропущены `services/__init__.py`, `pytest.ini`, `ruff.toml`, `.github/workflows/ci.yml`, `backlog.md`, `openspec/`.
- Существующий код не соответствует введённым лимитам: `pdf_handler.extract_text_and_coords` — 135 строк, `diff_engine.compute_diff` — 116, `main.compare` — 55, `vllm_client.stream_analysis_with_image` — 53, `vllm_client.stream_analysis` — 41.
- `README.md` указывает 59 тестов (фактически 75, `pytest --collect-only -q`), описывает шаг CI как `openspec validate --specs --strict` (фактически workflow выполняет `openspec validate --specs` — это осознанное отклонение, зафиксированное комментарием в `ci.yml` и пунктом P2.13 в `backlog.md`), и перечисляет в структуре проекта только часть фактических файлов.
- Спецификации проекта: `change-lifecycle`, `configuration`, `continuous-integration`, `pdf-hybrid-comparison`. Ни одна не описывает правила работы агента.
- `httpx` указан в `requirements.txt` как runtime-зависимость, но прямо используется только в `tests/test_streaming_errors.py`; фактически он приходит транзитивно с `openai`.

## Goals / Non-Goals

**Goals:**
- Правила проекта (`AGENTS.md`) и пользовательская документация (`README.md`) соответствуют фактическому состоянию репозитория по проверяемым фактам.
- Новые правила (приватность данных, язык ответов, дисциплина проверок, разрешения, достоверность, стиль кода, порядок работы с артефактами OpenSpec) закреплены в спецификации, а не только в прозе.
- Достоверность документации защищена технически — проверкой, которая падает при появлении ссылки на несуществующий элемент репозитория.
- Расхождения, которые этот change не закрывает, явно перечислены и отнесены к `backlog.md`, а не оставлены незамеченными.

**Non-Goals:**
- Рефакторинг существующих функций под лимиты длины (решение пользователя: только документация; долг — в `backlog.md`).
- Изменение состава зависимостей (`httpx`), API, продуктового кода и поведения приложения.
- Правка спецификации `continuous-integration` (расхождение по `--strict`) и возврат строгого режима в CI — отдельный change.
- Архивирование ранее закрытых пунктов `backlog.md` (P2.13) — затрагивается только текст актуального пункта.

## Decisions

**D1. AGENTS.md правится по фактам, структура пользователя сохраняется.**
Правка точечная: исправляются конкретные неверные утверждения и дополняются пробелы (структура проекта, ключевые API, DoD, стиль типизации). Разделы, не содержащие фактических ошибок (TL;DR, §8 «Правила взаимодействия», §9 «Git Workflow», §10 «OpenSpec Lifecycle»), остаются как есть.
*Альтернатива:* откатить `AGENTS.md` к прежней редакции — отклонена: новая редакция лучше структурирована, а расхождения точечны.

**D2. Лимиты длины вводятся с переходным периодом, долг фиксируется в `backlog.md`.**
В `AGENTS.md` формулировка: лимиты обязательны для нового и изменяемого кода; существующий код приводится к ним при изменении, а оставшийся долг (4 функции) перечислен в `backlog.md`.
*Альтернатива:* немедленный рефакторинг `extract_text_and_coords`, `compute_diff`, `compare`, `stream_analysis_with_image` — отклонена решением пользователя: это отдельный рискованный change с правкой продуктового кода.

**D3. Новая capability `agent-governance`, существующие capabilities не меняются.**
`change-lifecycle` описывает порядок работы с change'ом; `agent-governance` — правила агента в целом (приватность, язык, проверки, разрешения, достоверность, стиль). Требования `configuration`, `continuous-integration`, `pdf-hybrid-comparison` новой редакцией `AGENTS.md` не противоречат, поэтому дельты по ним не создаются.
*Альтернатива:* расширить `change-lifecycle` — отклонена: смешала бы порядок работы с change'ом и общие правила агента.

**D4. Достоверность документации фиксируется тестом `tests/test_docs_consistency.py`, а не новым шагом CI.**
Тест уже попадает в существующий прогон `pytest`, поэтому workflow не меняется. Проверяются: (а) существование файлов, упомянутых в `AGENTS.md` по шаблону `services/<имя>.py`, и явный список служебных файлов (`pytest.ini`, `ruff.toml`, `.github/workflows/ci.yml`, `backlog.md`, `openspec/`); (б) наличие в исходниках имён публичного API, названных в §14 `AGENTS.md` (`stream_analysis`, `stream_analysis_with_image`, `compute_diff`, `compute_diff_with_coords`, `extract_text_and_coords`, `render_page_to_png`, `read_environment`, `from_env`, `vllm_configured`). Пути вычисляются от корня репозитория (`Path(__file__).resolve().parents[1]`), чтобы тест не зависел от рабочего каталога.
*Альтернатива:* отдельный шаг CI со скриптом проверки — отклонена: лишняя поверхность в workflow при том же эффекте; правило «изменение кода = обновление тестов» неприменимо к документации, но сам тест — это код, и он получает покрытие правилом проверок.

**D5. В `README.md` убирается конкретное число тестов вместо его обновления.**
Число тестов меняется с каждым новым тестом, поэтому любое конкретное значение устареет и снова породит расхождение. В `README.md` остаётся формулировка «полный набор тестов» и команда получения фактического числа (`pytest --collect-only -q`), а требование «числовые утверждения соответствуют факту» сохраняется в спецификации на будущее.
*Альтернатива:* зафиксировать 75 — отклонена: возврат расхождения после следующего изменения тестов.

**D6. Описание шага CI в `README.md` приводится к факту, спека `continuous-integration` не меняется.**
В `README.md` указывается фактическая команда `openspec validate --specs` и отдельной сноской — причина отклонения (предсуществующие требования длиннее 500 символов в `pdf-hybrid-comparison`) и ссылка на `backlog.md` P2.13, где зафиксировано требование вернуть `--strict`. Расхождение «спека требует `--strict`, CI выполняет без `--strict»» объявляется, а не замалчивается и не «чинится» ослаблением требования в этом change.
*Альтернатива:* исправить спеку под факт — отклонена: это ослабило бы нормативное требование без отдельного решения владельца; исправление CI требует предварительной очистки спек, что выходит за рамки.

**D7. Формулировка о `input/` в `README.md` согласуется с `AGENTS.md` без раскрытия содержимого.**
В `README.md` остаётся факт: папка игнорируется Git и не является частью проекта; добавляется, что она приватная и агент не читает её без явного разрешения. Содержимое папки не описывается и не используется.

**D8. Правки вносятся в отдельной ветке и одним pull request.**
Ветка `docs/align-agents-md-with-project-reality` от `main`; в PR — правки `AGENTS.md`, `README.md`, `backlog.md`, новый тест и артефакты change'а; после подтверждения приёмки фактами (зелёный CI) — закрытие задач приёмки и архивирование change'а в том же PR.

## Risks / Trade-offs

- **[Тест согласованности блокирует PR при опечатке в документации]** → проверяются только явно перечисленные пути и упоминания вида `services/<имя>.py`; опечатка исправляется в том же PR, что соответствует правилу достоверности.
- **[Правило 40 строк будет воспринято как требование немедленно переписать существующий код]** → в `AGENTS.md` явно указан переходный период, конкретные нарушения перечислены в `backlog.md`, отдельного change'а по рефакторингу в план не входит.
- **[Расхождение со спецификацией `continuous-integration` по `--strict` сохраняется]** → объявлено явно в `README.md` и в `backlog.md` P2.13; закрывается отдельным change'ом после очистки требований длиннее 500 символов.
- **[Изменение формулировок `AGENTS.md` может пересечься с последующими правками пользователя]** → правки точечные, по проверяемым фактам; объём изменений минимален и виден в diff.
- **[Правило «документация не содержит чисел» снижает полезность `README.md` для читателя]** → дана команда получения фактического числа; число остаётся легко воспроизводимым.

## Migration Plan

1. Ветка `docs/align-agents-md-with-project-reality` от `main` (создание ветки — с разрешения пользователя).
2. Правки `AGENTS.md` → `README.md` → `backlog.md` → новый тест `tests/test_docs_consistency.py`.
3. Локально: `ruff check`, `ruff format --check`, `pytest`, `openspec validate --specs`.
4. Pull request в `main`; подтверждение приёмки фактами GitHub (ID PR + зелёный статус проверок).
5. В том же PR — закрытие задач приёмки в `tasks.md` и архивирование change'а.
6. Откат: изменение затрагивает только документацию и один новый тест; откат — revert PR, артефакты change'а удаляются вместе с ним.
