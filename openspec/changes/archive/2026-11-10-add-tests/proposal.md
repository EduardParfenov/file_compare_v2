## Why

В проекте отсутствует автоматизированное тестовое покрытие. Правила проекта (AGENTS.md, секция 10) требуют прохождения проверок — тесты, линтинг, сборка — перед вливанием pull-request в `main`, но папки `tests/` нет. Добавление тестов позволит защитить ядро приложения (движок diff, обработка PDF, конфигурация, роуты API) от регрессий при будущих изменениях и создаст основу для CI-гейтов.

## What Changes

- Создать папку `tests/` в корне проекта
- Добавить unit-тесты для `services/diff_engine.py`: `compute_diff`, разделение операций EQUAL/INSERT/DELETE на левую (`EQUAL` + `DELETE`) и правую (`EQUAL` + `INSERT`) панели
- Добавить unit-тесты для `services/pdf_handler.py`: извлечение текста и координат (`extract_text_and_coords`), рендер страницы в PNG (`render_page_to_png`), поведение при отсутствии текстового слоя в PDF
- Добавить unit-тесты для `config.py`: дефолтные значения `Settings`, загрузка из переменных окружения
- Добавить тесты для роутов `main.py`: `GET /api/v1/health`, `POST /api/v1/compare`
- Добавить `pytest` в `requirements.txt`
- Добавить `conftest.py` с фикстурами (TestClient FastAPI)

## Capabilities

### New Capabilities

Отсутствуют. Это изменение добавляет только тесты, оно не вводит новую системную возможность.

### Modified Capabilities

Отсутствуют. Изменение не вводит новые и не меняет существующие требования системы — оно только проверяет поведение, уже описанное в `openspec/specs/pdf-hybrid-comparison/spec.md`. Поэтому в `.openspec.yaml` изменения установлен флаг `skip_specs: true`.

## Impact

- Новая папка `tests/` в корне проекта
- Новая зависимость `pytest` в `requirements.txt` (`httpx` уже есть и может использоваться для тестирования API через TestClient)
- Исходный код приложения (`main.py`, `services/`, `static/`) не меняется — добавляется только тестовое покрытие
- Тесты не меняют внешнее поведение системы; пользовательский функционал и API остаются прежними
