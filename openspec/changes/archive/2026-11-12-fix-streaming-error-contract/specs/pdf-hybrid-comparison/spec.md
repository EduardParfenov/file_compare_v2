## MODIFIED Requirements

### Requirement: Кодирование изображения в Base64 перед отправкой в vLLM

Эндпоинт `/api/v1/ai-report-page` SHALL принимать изображение страницы как загруженный файл (UploadFile), читать его байты, кодировать в строку Base64 и передавать в клиент vLLM вместе с системным промптом и MIME-типом, чтобы Qwen3-VL-8B могла получить изображение для анализа.

#### Scenario: Изображение конвертируется в Base64 перед вызовом vLLM

- **WHEN** клиент отправляет POST-запрос на `/api/v1/ai-report-page` с полем `image` (PNG/JPEG) и полем `system_prompt`
- **THEN** бэкенд читает байты изображения, кодирует их в строку Base64 и вызывает `stream_analysis_with_image` с параметрами `image_base64`, `image_mime_type` и `system_prompt`, возвращая потоковый ответ (StreamingResponse)

#### Scenario: Ошибка vLLM возвращается как HTTP 502

- **WHEN** vLLM endpoint недоступен или отказывает до того, как клиенту передан первый фрагмент ответа
- **THEN** бэкенд возвращает HTTP 502 с понятным сообщением об ошибке, а пользователь может продолжить работу с обычным diff

## ADDED Requirements

### Requirement: Сбой vLLM до первого фрагмента ответа возвращается как HTTP 502

Потоковые маршруты `/api/v1/analyze` и `/api/v1/ai-report-page` SHALL возвращать HTTP 502 с понятным сообщением об ошибке, когда сбой vLLM произошёл до передачи клиенту первого фрагмента ответа: endpoint недоступен, соединение не установлено либо модель отказала до начала генерации.

#### Scenario: Сбой до первого фрагмента на маршруте анализа

- **WHEN** пользователь запускает ИИ-анализ изменений, а vLLM недоступен либо отказывает до начала генерации
- **THEN** маршрут возвращает HTTP 502 с понятным сообщением об ошибке, а не HTTP 200 с пустым телом ответа

#### Scenario: Сбой до первого фрагмента на маршруте отчёта по странице

- **WHEN** пользователь запускает ИИ-отчёт по странице, а vLLM недоступен либо отказывает до начала генерации
- **THEN** маршрут возвращает HTTP 502 с понятным сообщением об ошибке, а не HTTP 200 с пустым телом ответа

### Requirement: Сбой во время стрима передаётся кадром события error

Если сбой vLLM происходит после того, как клиенту уже передан хотя бы один фрагмент ответа, система SHALL передать ошибку в потоке SSE явным кадром события `error` с полезной нагрузкой `data: {"error": "<сообщение>"}` и после этого закрыть поток штатно, не обрывая передачу данных на полуслове.

#### Scenario: Обрыв генерации в середине ответа

- **WHEN** модель передала часть ответа, а затем соединение с vLLM оборвалось
- **THEN** клиент получает в потоке кадр `event: error` с текстом ошибки, а ранее переданные фрагменты остаются в выводе

#### Scenario: Успешный стрим не содержит кадра ошибки

- **WHEN** генерация завершилась без ошибок
- **THEN** поток содержит только кадры данных и не содержит кадра `event: error`

### Requirement: Фронтенд отображает ошибку стриминга пользователю

Фронтенд SHALL разбирать поток SSE с учётом поля `event:`, показывать текст ошибки из кадра `event: error` пользователю в панели ИИ-аналитики, сохранять уже полученный частичный вывод и возвращать элемент управления запуском в доступное состояние. Обрыв потока на уровне сети SHALL также сопровождаться явным сообщением пользователю.

#### Scenario: Кадр ошибки показан пользователю

- **WHEN** бэкенд передал кадр `event: error` во время ИИ-анализа
- **THEN** в панели ИИ-аналитики видно текст ошибки, а частичный вывод остаётся на месте

#### Scenario: Обрыв соединения во время стрима

- **WHEN** соединение с бэкендом прервано в середине ИИ-анализа
- **THEN** пользователь видит сообщение об обрыве вместо пустого вывода, а кнопка запуска снова доступна

#### Scenario: Успешный стрим не показывает ошибку

- **WHEN** ИИ-анализ завершился без ошибок
- **THEN** блок с сообщением об ошибке остаётся скрытым, а весь ответ выведен в панели

### Requirement: SSE-ответ отдаётся без буферизации промежуточным прокси

Потоковые ответы с MIME-типом `text/event-stream` SHALL сопровождаться заголовками `Cache-Control: no-cache` и `X-Accel-Buffering: no`, чтобы реверс-прокси не буферизовал поток и не задерживал доставку кадров.

#### Scenario: Заголовки против буферизации

- **WHEN** клиент запрашивает `/api/v1/analyze` или `/api/v1/ai-report-page`
- **THEN** ответ содержит заголовки `Cache-Control: no-cache` и `X-Accel-Buffering: no`

### Requirement: Сообщения об ошибках не раскрывают внутренний адрес эндпоинта ИИ-модели

Сообщения об ошибках, возвращаемые пользователю (в теле HTTP 502 и в кадре `event: error`), SHALL NOT содержать внутренний адрес (URL) эндпоинта ИИ-модели, ключи доступа и иные сведения о внутренней конфигурации; детали ошибки фиксируются только в серверных логах.

#### Scenario: Внутренний адрес не попадает к пользователю

- **WHEN** пользователь получает HTTP 502 или кадр `event: error` из-за сбоя vLLM
- **THEN** текст сообщения не содержит внутренний адрес эндпоинта ИИ-модели и ключи доступа
