## REMOVED Requirements

### Requirement: Загрузка переменных окружения из файла .env

**Reason**: Требование содержало сценарий «Переменные окружения из оболочки приоритетнее .env», название которого противоречило его собственному телу (тело утверждало, что приоритет у `.env`) и фактическому поведению приложения. Требование заменено требованием с явно зафиксированным порядком приоритетов.

**Migration**: Вместо требования «Загрузка переменных окружения из файла .env» действует требование «Приоритет файла .env над переменными окружения оболочки»: оно покрывает те же случаи (дефолтные значения при отсутствии `.env`, значения из `.env` вместо дефолтов) и дополнительно фиксирует приоритет источников, семантику пустых значений и ключей без знака равенства.

## ADDED Requirements

### Requirement: Приоритет файла .env над переменными окружения оболочки

Система SHALL читать переменные окружения из файла `.env` в корне проекта через библиотеку `python-dotenv` при старте приложения, чтобы значения из `.env` были доступны в `config.settings`. Значения из файла `.env` SHALL иметь приоритет над значениями, заданными в окружении оболочки: файл `.env` перекрывает переменную оболочки, если она задана в обоих источниках.

#### Scenario: Переменные из .env переопределяют дефолты

- **WHEN** файл `.env` существует в корне проекта и содержит `VLLM_API_URL=http://custom:9000/v1`
- **THEN** `config.settings.VLLM_API_URL` возвращает `"http://custom:9000/v1"` вместо дефолтного `"http://localhost:8000/v1"`

#### Scenario: Дефолтные значения применяются, когда .env отсутствует

- **WHEN** файл `.env` отсутствует и переменные окружения не заданы в оболочке
- **THEN** `config.settings.VLLM_API_URL` возвращает `"http://localhost:8000/v1"` (дефолтное значение)

#### Scenario: Значения из .env приоритетнее переменных окружения оболочки

- **WHEN** файл `.env` содержит `VLLM_API_URL=http://from-dotenv:9000/v1`, а в оболочке экспортировано `VLLM_API_URL=http://from-shell:9000/v1`
- **THEN** `config.settings.VLLM_API_URL` возвращает `"http://from-dotenv:9000/v1"` (значение из `.env` приоритетнее)

#### Scenario: Пустое значение в .env перекрывает значение оболочки

- **WHEN** файл `.env` содержит `VLLM_API_KEY=` (пустое значение), а в оболочке экспортировано `VLLM_API_KEY=shell-key`
- **THEN** `config.settings.VLLM_API_KEY` возвращает `""` (пустая строка, а не значение из оболочки)

#### Scenario: Ключ без знака равенства игнорируется

- **WHEN** файл `.env` содержит строку `VLLM_API_KEY` без знака `=`, а в оболочке экспортировано `VLLM_API_KEY=shell-key`
- **THEN** `config.settings.VLLM_API_KEY` возвращает `"shell-key"` (значение из оболочки сохраняется)

### Requirement: Независимость конфигурации от рабочего каталога

Система SHALL определять путь к файлу `.env` относительно корня проекта, а не относительно текущего рабочего каталога и не путем поиска вверх по дереву каталогов. Файл `.env`, расположенный вне корня проекта, SHALL NOT использоваться для конфигурации приложения.

#### Scenario: .env из родительской директории не подхватывается

- **WHEN** в корне проекта отсутствует файл `.env`, но в родительской директории проекта присутствует файл `.env` с заданными значениями
- **THEN** приложение использует дефолтные значения настройки, а не значения из родительской директории

#### Scenario: Результат конфигурации не зависит от текущего рабочего каталога

- **WHEN** приложение запускается из произвольного рабочего каталога, отличного от корня проекта
- **THEN** конфигурация приложения совпадает с конфигурацией при запуске из корня проекта

#### Scenario: Проверка конфигурации не зависит от локального окружения разработчика

- **WHEN** выполняется автоматическая проверка конфигурации на машине, где в корне проекта присутствует локальный файл `.env` с произвольными значениями
- **THEN** результат проверки определяется только явно переданными входными данными проверки и не зависит от наличия или содержимого локального `.env`

### Requirement: Отсутствие побочных эффектов при чтении конфигурации

Система SHALL вычислять конфигурацию приложения без изменения переменных окружения текущего процесса: чтение файла `.env` SHALL NOT приводить к записи его значений в окружение процесса.

#### Scenario: Окружение процесса не изменяется при чтении .env

- **WHEN** приложение читает файл `.env`, содержащий `VLLM_API_URL=http://from-dotenv:9000/v1`
- **THEN** переменная `VLLM_API_URL` в окружении текущего процесса сохраняет значение, заданное до чтения, либо остаётся не заданной

#### Scenario: Конфигурация доступна после чтения .env

- **WHEN** приложение читает файл `.env`, содержащий `VLLM_API_URL=http://from-dotenv:9000/v1`
- **THEN** `config.settings.VLLM_API_URL` возвращает `"http://from-dotenv:9000/v1"`
