## Служебные замечания по реализации

- **Область видимости фикстуры браузера уточнена по ходу реализации (design.md D5 обновлён).** Первоначально `chromium_browser` была спроектирована на session scope. При полном прогоне выяснилось, что `tests/test_streaming_errors.py` падает с `RuntimeError: asyncio.run() cannot be called from a running event loop`. Причина измерена отдельно: открытый контекст `sync_playwright()` держит в главном потоке работающий event loop asyncio — внутри контекста `asyncio.run()` падает, после выхода из контекста работает. Поэтому контекст Playwright закрывается вместе с модулем (`chromium_browser` — module scope). `live_server` остался на session scope: uvicorn работает в отдельном потоке со своим циклом, а работающий цикл — потоковая переменная asyncio, поэтому главный поток тестов он не затрагивает.
- **Список JS-ошибок общий на модуль.** Сценарий с намеренно падающим потоком (`test_ai_error_is_shown_instead_of_empty_explanation`) добавляет в список ожидаемые ошибки консоли, которые иначе «заразили» бы последующие проверки того же модуля. Поэтому тесты сравнивают не весь список, а дельту с момента начала теста (хелпер `_new_js_errors`). Смысл проверки не изменился: тест по-прежнему требует, чтобы конкретный тест не вносил новых ошибок JavaScript.
- **`#aiEmpty` оформлен в разметке, а не в `static/styles.css`.** Дизайн D3 допускал правку `static/styles.css`, но для блока, повторяющего оформление `#aiError`, достаточно тех же Tailwind-классов с нейтральными цветами. Файл `static/styles.css` не менялся.
- **Тест переключателя кликает по `#aiPanelToggle`, а не по `#aiPanelHeader`.** Индикатор присутствует и в исходной разметке, поэтому падение на старом коде демонстрирует сам дефект (недоступная `toggleAiPanel`), а не отсутствие нового идентификатора. Отдельно проверяется и клик по самой шапке (`#aiPanelHeader`).
- `static/app.js`: функция `toggleAiPanel()` осталась модульной и не публикуется в `window` — это и есть суть исправления по design.md D1.
