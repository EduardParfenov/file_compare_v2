## Context

Текущее состояние: `config.py` использует только `os.getenv()` для чтения переменных окружения. Файл `.env` в корне проекта игнорируется — переменные из него не подгружаются в `os.environ`. Пользователь должен вручную экспортировать переменные в оболочку перед запуском, что contradиктует сценарию из `AGENTS.md` и `README.md` (`cp .env.example .env`). Библиотека `python-dotenv` уже есть в `requirements.txt`, но не используется.

## Goals / Non-Goals

**Goals:**
- Добавить `load_dotenv()` в `config.py`, чтобы `.env` загружался при импорте модуля.
- Убедиться, что значения из `.env` переопределяют дефолты в `Settings`.
- Убедиться, что переменные из оболочки (`os.environ`) приоритетнее значений из `.env` (стандартное поведение `load_dotenv`).

**Non-Goals:**
- Не менять логику `Settings` или имена полей.
- Не добавлять проверку валидности значений (валидация остаётся на усмотрение вызывающего кода).
- Не менять `.env.example` или `.env` (они уже существуют).

## Decisions

### Вызов load_dotenv() в config.py при импорте модуля

**Почему выбран:** `config.py` — центральное место чтения настроек, импортируемое во всём приложении (`main.py`, `services/`, `tests/`). Вызов `load_dotenv()` один раз при импорте гарантирует, что все модули видят переменные из `.env`.

**Альтернативы, рассмотренные:**
- **Вызов load_dotenv() в main.py:** отклонён — тесты и другие модули, импортирующие `config` напрямую, не увидят переменные из `.env`.
- **Явный вызов load_dotenv() в каждом модуле:** отклонён — дублирование кода, легко забыть вызвать в новом модуле.

### Порядок приоритета: os.environ > .env > дефолты

**Почему выбран:** стандартное поведение `python-dotenv` — `load_dotenv()` не перезаписывает уже существующие переменные в `os.environ`. Это соответствует ожиданиям: переменные из оболочки имеют最高 приоритет.

## Risks / Trade-offs

[.env содержит секреты] → файл `.env` уже в `.gitignore`, не попадает в Git. Риск минимальный.

[load_dotenv может перезаписать системные переменные] → `python-dotenv` по умолчанию `override=False`, поэтому существующие переменные `os.environ` не перезаписываются. Безопасно.

## Migration Plan

Изменение обратносовместимо: если `.env` отсутствует, приложение работает с дефолтами (как и раньше). Если `.env` есть, переменные подхватываются автоматически. Откат — убрать строку `load_dotenv()` из `config.py`.
