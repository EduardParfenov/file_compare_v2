## Context

См. `proposal.md`. Ниже — техническое состояние, определяющее подход.

Факты (воспроизведено экспериментально на синтетических PDF, пара: абзац со страницы 3 переносится на страницу 5):

- Пайплайн: `extract_text_and_coords` (`full_text = "\n".join(page_texts)`) → `compute_diff` (diff-match-patch) → `mapWordsToOps` (`static/app.js`). Слово помечается как DELETE/INSERT, если попадает в блок diff панели.
- DMP-diff при перемещении выдаёт артефакт: `INSERT Z + EQUAL P + DELETE Z`, где `Z` — текст между старым и новым положением перемещённого фрагмента (одинаковый в обеих версиях), `P` — перемещённый абзац. Все помеченные слова присутствуют в другой версии на тех же страницах (в прогоне: `present_in_B_page_N=True` на левой панели и `present_in_A_page_N=True` на правой).
- `diff_cleanupSemantic`, `diff_cleanupSemanticLossless`, `diff_cleanupMerge` (diff-match-patch 20230430) на этом сценарии не меняют дифф.

Проверено: PyMuPDF 1.24 — `page.get_text("text", clip=Rect(0, 0, w, h - 40))` и `page.get_text("words", clip=Rect(0, 0, w, h - 40))` возвращают текст и слова, ограниченные верхней границей полосы (блоки с `y0 >= height - 40` не попадают в `text` при клипе `main_clip` и не попадают в `words` при клипе `main_clip`).

## Goals / Non-Goals

**Goals:**

- При переносе текста между страницами перемещённый текст не помечается как DELETE/INSERT на обеих панелях.
- Колонтилы распознаются (`footer_text`), не участвуют в основном diff.
- Реальные изменения (неперемещённые) по-прежнему помечаются.

**Non-Goals:**

- Ревизия алгоритма DMP-diff (не помогает в этом сценарии).
- Визуализация `footer_diff` в UI; подсветка колонтильных слов на canvas (поле доступно в ответе API).
- Regex-/блоковая эвристика обнаружения колонтилов — альтернативы из `BACKLOG-header-footer-diff.md` (Варианты Б, В, Е) отклонены.

## Decisions

### D1. Геометрическое выделение колонтилов: нижняя полоса `FOOTER_BAND = 40.0`

Колонтилы — текст в нижней полосе страницы, высота полосы — `FOOTER_BAND = 40.0` пунктов. Экстракция в `extract_text_and_coords`:

```python
footer_top = max(0.0, rect.height - FOOTER_BAND)
main_clip = fitz.Rect(0, 0, rect.width, footer_top)
footer_clip = fitz.Rect(0, footer_top, rect.width, rect.height)
text = page.get_text("text", clip=main_clip) or ""
footer_text = page.get_text("text", clip=footer_clip) or ""
raw_words = page.get_text("words", clip=main_clip) or []
```

- **Почему:** геометрическое выделение не зависит от содержимого (номера страниц, шифры, организации); исключение из `text`/`words`/`full_text` — прямо следует из требования «не учитываться как холст основного текста»; сравнение колонтилов отдельно — поле `footer_diff` в ответе API.
- **Альтернатива A (Вариант А из `BACKLOG-header-footer-diff.md` — regex-фильтрация строк в `full_text`) — отклонена:** рассинхрон `global_char_start/end` слов с `char_start/end` блоков diff.
- **Альтернатива B (Вариант Б — блоковое определение колонтилов по координатам) — отклонена:** более сложная логика без выигрыша в точности.
- **Честное ограничение:** футер, расположенный ближе к краю, чем 40 pt от нижнего края, может попасть в основной текст — эвристика, сужается стороной (см. также BACKLOG-header-footer-diff.md).

### D2. Перемещённый текст — подавление по тексту слова в другой версии

В `mapWordsToOps` (`static/app.js`) после блокового маркирования (приоритет DELETE/INSERT над EQUAL) добавлено подавление:

```js
if (
  wordOp !== "EQUAL" &&
  w.word &&
  otherDocText &&
  otherDocText.includes(w.word)
) {
  wordOp = "EQUAL";
}
```

где `otherDocText` — основной текст другой версии (конкатенация `pages[].text`).

- **Почему:** DMP генерирует swap-артефакты при перемещении (DELETE Z + EQUAL P + INSERT Z); слова Z — идентичны в обеих версиях, подсветка на них — ложная. Подавление по присутствию в другой версии делает перемещение невидимым, сохраняя реальные удаления/вставки (слово отсутствует в другой версии — не подавляется).
- **Честное ограничение:** дублирующие слова (тот же текст есть и в теле другой версии) могут быть незамеченными при перемещении; интеграционный тест на синтетической паре (перенос со стр. 2 на стр. 3) подтверждает отсутствие ложных пометок.

### D3. `footer_diff` — отдельная ветка сравнения

`/api/v1/compare` возвращает `footer_diff` — `compute_diff(footer_a, footer_b)` над конкатенацией `footer_text` обеих версий (пустые тексты — пустой diff). Фронтенд сохраняет его в `state.footerDiff`.

- **Почему:** колонтилы вынесены из `full_text`, чтобы изменения колонтилов (нумерация страниц) не попадали в основные панели; сравнение остаётся доступным как отдельный контракт ответа API.
