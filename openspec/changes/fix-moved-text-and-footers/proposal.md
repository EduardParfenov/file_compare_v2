## Why

При переносе текста на другую страницу пользователь видит ложные изменения: diff-match-patch выдаёт DELETE слева и INSERT справа на страницах, где текст действительно не изменился. Воспроизведено на паре синтетических PDF: перенос абзаца со страницы 3 на страницу 5 → левая панель помечает слова страниц 3–5 как DELETE, правая — как INSERT, хотя менялся только перемещённый абзац (блоки diff содержат одинаковый текст на страницах 3–5, и все помеченные слова присутствуют в другой версии на тех же страницах). `diff_cleanupSemantic` в этом сценарии не меняет дифф — бэкенд решить проблему не может.

Когда в документах есть колонтилы (номера страниц, шифры документов вида `1101/5-П-АСУ-...`, постоянные маркеры организации), изменения колонтилов (например, нумерация страниц) попадают в сравнение основного текста и усиливают каскад ложных пометок на страницах, которые не менялись.

## What Changes

- `services/pdf_handler.py`: в `extract_text_and_coords` колонтилы — текст в нижней полосе страницы (`FOOTER_BAND = 40.0` пунктов) — выносятся в новое поле `pages[i]["footer_text"]`; `text`, `words`, `full_text` (основной холст diff) больше не содержат колонтильного текста (`get_text("text", clip=main_clip)` / `get_text("words", clip=main_clip)`).
- `main.py`: `/api/v1/compare` сравнивает колонтилы отдельно — в ответ добавляется поле `footer_diff` (diff объединённых `footer_text` обеих версий, `compute_diff`).
- `static/app.js`: в `mapWordsToOps` подавляются DELETE/INSERT-пометки для слов, текст которых есть в основном тексте другой версии — перемещённый текст считается не изменённым. Добавлена функция `otherDocText(panelKey)` (основной текст другой версии) и сохранение `state.footerDiff`.
- Тесты: `tests/test_pdf_handler.py` (колонтилы распознаются и исключены из `text`/`full_text`; без колонтилов `footer_text == ""`), `tests/test_frontend_diff_mapping.py` (порт `map_words_to_ops` синхронизирован с подавлением; unit-тесты подавления; интеграционный тест переноса со стр. 2 на стр. 3 — ложные пометки отсутствуют), `tests/test_main.py` (`footer_diff` в ответе `/api/v1/compare`).

## Impact

Затронуты файлы: `services/pdf_handler.py`, `main.py`, `static/app.js`, `tests/test_pdf_handler.py`, `tests/test_frontend_diff_mapping.py`, `tests/test_main.py`.

Поведение изменяется следующим образом:

1. При переносе текста между страницами перемещённый текст больше не подсвечивается как изменение на обеих панелях — проверено через интеграционный тест на синтетических PDF (перенос со стр. 2 на стр. 3).
2. Изменения колонтилов больше не попадают в основные панели diff-результата; они сравниваются отдельно (поле `footer_diff` в ответе API).
3. Реальные изменения (удаление/добавление слов основного текста) по-прежнему подсвечиваются.

Публичный API Python не меняется (только добавляется поле `footer_text` в структуру `pages` и `footer_diff` в ответ `/api/v1/compare`).

Вне объёма change'а (сознательно): визуализация `footer_diff` в UI; ревизия DMP-алгоритма (`diff_cleanupSemantic` и др. — не решают этот сценарий); regex-/блоковая эвристика обнаружения колонтилов (альтернативы — `BACKLOG-header-footer-diff.md`, Варианты А/Б/В).
