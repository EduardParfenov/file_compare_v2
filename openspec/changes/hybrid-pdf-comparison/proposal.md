## Why

Пользователям требуется сравнивать две версии одного PDF-документа и видеть одновременно два рода изменений: (1) текстовые правки — в стиле Git Split Diff (удаленное зачеркнуто слева, добавленное подсвечено зеленым справа), и (2) изменения верстки, таблиц, логотипов и шрифтов — через визуальный анализ мультимодальной VL-модели Qwen3-VL-8B. Текущего решения, дающего только плоское текстовое сравнение, недостаточно: без привязки к координатам на странице и без ИИ-разбора пользователь теряет контекст того, где именно на странице произошло изменение и что оно означает с точки зрения смысла документа.

## What Changes

- Новый веб-сервис на Python 3.11 + FastAPI (Uvicorn) для гибридного сравнения двух версий PDF-документов.
- `services/pdf_handler.py` — извлечение текста и координат слов/блоков через PyMuPDF (`fitz`), включая `page.get_text("words")` / `page.get_text("blocks")` для рендера прозрачного diff-слоя поверх страниц.
- `services/diff_engine.py` — дифф-движок на базе Google `diff-match-patch`; разделение операций EQUAL / INSERT / DELETE на два параллельных потока для левой (исходная версия) и правой (измененная версия) панелей в стиле Git Split Diff; возврат JSON с HTML-разметкой и метаданными для обеих панелей.
- `services/vllm_client.py` — асинхронный клиент vLLM (OpenAI-совместимый API) со стримингом ответа через FastAPI `StreamingResponse` (SSE).
- `main.py` — точка входа FastAPI: CORS, роуты сравнения и стриминга ИИ-анализа.
- `static/index.html`, `static/app.js`, `static/styles.css` — фронтенд: два окна сравнения side-by-side, рендер страниц PDF через pdf.js в `<canvas>`, абсолютно позиционированный прозрачный HTML-слой с текстовыми элементами поверх canvas, синхронный скроллинг с привязкой к текстовым якорям (блоки), боковая сворачиваемая панель "AI Аналитика" со стримингом и кнопкой отчета по странице.
- `config.py` — чтение всех настроек из переменных окружения (`.env`) с безопасным fallback на дефолтные значения.
- `requirements.txt`, `.env.example`, `.gitignore`, `README.md` — управление зависимостями, виртуальное окружение `.venv/`, секреты, инструкции по развертыванию.
- В документации зафиксировано: папка `input/` содержит пользовательские файлы и игнорируется проектом.

## Capabilities

### New Capabilities

- `pdf-hybrid-comparison`: гибридное сравнение двух версий PDF — визуальный Git Split Diff поверх оригинальной верстки страниц (pdf.js + координаты слов/блоков из PyMuPDF) и ИИ-анализ изменений через локальную VL-модель Qwen3-VL-8B (vLLM, streaming). Каждая возможность описана в `specs/pdf-hybrid-comparison/spec.md`.

- (нет — это новая, ранее не существующая возможность; существующих спецификаций в проекте нет)

## Impact

- Новый проектный код: `main.py`, `services/__init__.py`, `services/pdf_handler.py`, `services/diff_engine.py`, `services/vllm_client.py`, `config.py`, `static/index.html`, `static/app.js`, `static/styles.css`.
- Окружение и безопасность: `.venv/` (изолированное виртуальное окружение), `.env` (реальные секреты, не попадает в Git), `.env.example` (публичный шаблон), `.gitignore`, `README.md`.
- Зависимости: `fastapi`, `uvicorn`, `pymupdf`, `diff-match-patch`, `openai`; на фронтенде — pdf.js (через CDN).
- Внешний сервис: vLLM endpoint (`http://172.16.48.122:8002/v1`, модель `qwen3-vl-8b`, ключ из `.env`).
- Конфигурация строго через `.env` (URL vLLM, имя модели, хост/порт FastAPI, CORS) с дефолтными значениями при отсутствии `.env` — код готов к запуску в Docker и за Nginx (относительные пути на фронтенде, `/api/v1/...`).
- Папка `input/` — пользовательские файлы; игнорируется в `.gitignore` и упомянута в `README.md`.
