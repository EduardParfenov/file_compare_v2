## Context

Новый веб-сервис для гибридного сравнения двух версий PDF-документов. Мотивация и объем изменений см. в `proposal.md` (разделы "Why" и "What Changes"). Функциональные требования см. в `specs/pdf-hybrid-comparison/spec.md`. Проект создается с нуля (зеленое поле), существующих спецификаций и кода в `openspec/specs/` нет.

## Goals / Non-Goals

**Goals:**
- Сравнение текста двух версий PDF в формате Git Split Diff (левая панель — исходная версия с удалениями, правая — измененная версия с добавлениями).
- Привязка текстовых элементов к координатам на страницах PDF (PyMuPDF `get_text("words")`/`get_text("blocks")`) и рендер прозрачного HTML-слоя поверх подложки страниц (pdf.js + `<canvas>`).
- Синхронный скроллинг окон, привязанный к текстовым якорям (блокам), а не к пикселям.
- ИИ-анализ изменений через локальный vLLM (Qwen3-VL-8B) со стримингом ответа в боковую панель.
- ИИ-отчет по текущей странице с визуальным контекстом (изображение страницы + системный промпт).
- Конфигурация строго через `.env` с fallback на дефолтные значения (`config.py`).
- Изоляция зависимостей в `.venv/`; `.env` и `input/` не попадают в Git.
- Код Docker-friendly и готовый к работе за Nginx (относительные API-пути `/api/v1/...`, без жестко заданных хостов).

**Non-Goals:**
- Реализация Dockerfile, docker-compose и конфигов Nginx (отложено на позже).
- Конвертация PDF в Markdown или любой другой промежуточный формат для отображения.
- Поддержка форматов, отличных от PDF (например, DOCX).
- Обработка отсканированных PDF без текстового слоя — только уведомление об ошибке/пустом результате.
- Аутентификация, авторизация и управление пользователями.

## Decisions

**Стек бэкенда: Python 3.11 + FastAPI (async) + Uvicorn.**
- Обоснование: отвечает требованиям заказчика; асинхрономность нужна для стриминга ответов vLLM без блокировки事件 loop; FastAPI удобен для определения роутов и валидации данных.
- Альтернативы: Flask (синхронный, хуже подходит для streaming), Starlette напрямую (требует больше бойлерплейта).

**Алгоритм diff: Google `diff-match-patch`.**
- Обоснование: точный посимвольный comparisons строк, дает массив операций EQUAL/INSERT/DELETE, прямо поддерживающий разделение на левую и правую панели.
- Альтернативы: `difflib` (менее точный для посимвольного вывода), `pydiff`/`python-Levenshtein` (только расстояние, без пооперационного вывода).

**Извлечение текста и координат: PyMuPDF (`fitz`).**
- Обоснование: быстрое извлечение текста, `page.get_text("words")`/`get_text("blocks")` дают координаты для diff-слоя, рендер страниц в PNG для VL-анализа.
- Альтернативы: pdfplumber (больше ориентирован на таблицы, медленнее), PyPDF2 (нет координат в нужном виде).

**vLLM через асинхронный клиент `openai` + FastAPI `StreamingResponse` (SSE).**
- Обоснование: vLLM предоставляет OpenAI-совместимый API; потоковый ответ передается пользователю в реальном времени.
- Альтернативы: HTTP-клиент `httpx` напрямую (больше ручной работы по парсингу SSE), синхронный клиент (заблокирует事件 loop).

**Фронтенд: HTML5 + TailwindCSS + Vanilla JavaScript, pdf.js для рендера страниц.**
- Обоснование: отсутствие лишних зависимостей сборки, простота развертывания как статических файлов, pdf.js — де-факто стандарт рендера PDF в браузере.
- Альтернативы: React/Vue (избыточно для этого объема), pdf2svg/иные библиотеки (menos распространенные).

**Конфигурация: `config.py` с `os.getenv` и дефолтными значениями.**
- Обоснование: встроенная библиотека, нет лишней зависимости (`pydantic-settings` можно добавить позже), безопасный fallback при отсутствии `.env`.
- Альтернатива: `pydantic-settings` (более строгая валидация, но дополнительная зависимость).

**Синхронный скроллинг с привязкой к текстовым блокам (якорям).**
- Обоснование: предотвращает рассинхронизацию при вставке больших абзацев; неизмененные абзацы остаются друг напротив друга.
- Альтернатива: скроллинг по пикселям (простой, но быстро рассинхронизируется при разном объеме текста).

**Папка `input/` игнорируется.**
- Обоснование: пользовательские файлы, не часть кода проекта; фиксируется в `.gitignore` и `README.md`.

## Risks / Trade-offs

- [vLLM endpoint недоступен] → ИИ-анализ и отчет по странице не работают; нужно отображать понятную ошибку и позволять пользователю продолжить работу с обычным diff.
- [PDF без текстового слоя / сложная верстка] → координаты слов могут быть неточными или отсутствовать; diff-слой будет неполным; требуется уведомление пользователя.
- [Рассинхронизация скроллинга при大きных вставках] → блокировка ("замирание") одного окна может показаться пользователю задержкой; нужно четкое визуальное обозначение компенсирующего пространства.
- [Секреты в `.env`] — риск попадания в Git смягчается `.gitignore`; `.env.example` без реальных значений.
- [CORS при развертывании за Nginx] — нужно корректно настроить CORS в `main.py` и, позднее, в Nginx (заголовки проксирования).
- [Производительность рендера большого количества страниц] — pdf.js рендерит только видимые страницы; необходимо ленивое/отложенное рендеринг вне зоны просмотра.

## Migration Plan

- Локальная разработка: создать `.venv`, установить `requirements.txt`, скопировать `.env.example` в `.env` и заполнить реальные значения, запустить `uvicorn main:app --reload`.
- Далее (отдельная задача): добавить Dockerfile, docker-compose и Nginx-конфиг; при развертывании за Nginx настроить проксирование `/api/v1/...` на бэкенд и раздачу `static/` как статики.
