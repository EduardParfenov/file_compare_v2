## Why

Новая редакция `AGENTS.md` (правила проекта) разошлась с фактическим состоянием репозитория: в ней перечислены несуществующий модуль `services/ai_context.py`, несуществующий метод `VllmClient.stream_chat()`, конфиг линтера в несуществующем `pyproject.toml` (фактически — `ruff.toml`), несуществующее поле `settings.output_dir` и несуществующий тип `TextBlock` в примерах кода. Агент, следующий этим правилам, получает заведомо неверные подсказки об API и тратит время на поиск отсутствующих файлов.

Одновременно новые правила (приватность `input/` и `.env`, русский язык ответов, дисциплина `ruff`/тестов, достоверность документации) не отражены ни в одной спецификации — они существуют только как проза, которую нельзя ни проверить, ни откатить единообразно. Смежные артефакты тоже рассинхронизированы: `README.md` указывает 59 тестов вместо фактических 75, описывает команду валидации OpenSpec в CI как `openspec validate --specs --strict`, хотя workflow выполняет её без `--strict`, и не отражает `tests/`, `pytest.ini`, `ruff.toml`, `openspec/`, `backlog.md` и CI-workflow в описании структуры проекта.

## What Changes

**`AGENTS.md` — приведение к фактическому состоянию (правка документации):**
- §3 «Структура проекта»: убрать несуществующий `services/ai_context.py`; добавить фактические элементы репозитория — `services/__init__.py`, `pytest.ini`, `ruff.toml`, `.github/workflows/ci.yml`, `backlog.md`, `openspec/`, `tests/`.
- §5 «Стиль кода»: указать фактический файл конфигурации линтера — `ruff.toml` (не `pyproject.toml`); заменить рекомендацию `from typing import Optional, List, Dict` на стиль проекта — `from __future__ import annotations` и встроенные generic-типы (`list[str]`, `dict[str, str]`, `X | None`).
- §5 «Ограничения»: лимиты длины функции, вложенности и числа аргументов ввести как норму для нового и изменяемого кода, с переходным периодом для существующего кода (долг фиксируется в `backlog.md`); убрать впечатление, что текущий кодек уже соответствует этим лимитам.
- §6 «Примеры правильного кода»: привести примеры к фактическим API — `extract_text_and_coords(pdf_path: str) -> dict` (без несуществующего `TextBlock`), `PdfHandlerError`; в примере обработки ошибок использовать реальный `vllm_client.stream_analysis(prompt)` вместо несуществующего `stream_chat(messages)`.
- §7 «Частые ошибки агента»: заменить пример `settings.output_dir` (такого поля в `Settings` нет) на реальный способ построения путей.
- §11 «Definition of Done»: уточнить контракт `GET /api/v1/health` — `status: "ok"` вместе с именем модели и признаком настройки подключения, а не только `{"status": "ok"}`.
- §14 «Ключевые API»: назвать фактические функции — `VllmClient.stream_analysis()` и `VllmClient.stream_analysis_with_image()` (вместо `stream_chat()`), `compute_diff()` и `compute_diff_with_coords()`, `extract_text_and_coords()` → `dict`, `render_page_to_png()`; удалить упоминание `services/ai_context.py`; уточнить роль `httpx` (транзитивная зависимость `openai`, прямо используется в тестах).
- §4.3 «Тестовые данные»: отметить, что каталога `tests/fixtures/` в проекте нет — тесты используют синтетические PDF через `tmp_path` и моки.

**`README.md` — синхронизация с фактическим состоянием:**
- Описание структуры проекта дополнить `tests/`, `pytest.ini`, `ruff.toml`, `openspec/`, `backlog.md` и `.github/workflows/ci.yml`.
- Актуализировать число тестов: 59 → 75 (два упоминания).
- Исправить описание шага CI «Валидирует артеакты OpenSpec (`openspec validate --specs --strict`)» на фактическое `openspec validate --specs` (без `--strict`), с указанием причины отклонения.
- Согласовать формулировку о `input/` с `AGENTS.md`: папка приватная, игнорируется Git, агент не читает её без явного разрешения.

**Новая capability `agent-governance`** — спецификация правил работы агента и разработчика (приватность данных, язык ответов, дисциплина линтера и тестов, порядок работы с OpenSpec и git, достоверность документации, стиль кода). Требует отдельной дельты в `specs/agent-governance/spec.md`.

**`backlog.md`:**
- Отметить результаты текущего change'а в пункте P2.13 «Привести в порядок артефакты и документацию».
- Добавить пункт долга: приведение существующих функций к лимитам длины (`extract_text_and_coords` — 135 строк, `compute_diff` — 116, `compare` — 55, `stream_analysis_with_image` — 53).

**Техническая фиксация достоверности (тест, не рефакторинг кода):**
- `tests/test_docs_consistency.py` — проверка того, что упомянутые в `AGENTS.md` модули `services/*.py`, файл конфигурации линтера и документированные имена публичного API существуют. Это техническое обеспечение нового требования «правила проекта достоверны», а не изменение продуктового кода.

**Вне области этого change'а (явные non-goals):**
- Рефакторинг существующих функций под лимиты длины — отдельная задача (долг в `backlog.md`).
- Перенос `httpx` из `requirements.txt` в `requirements-dev.txt` — зависимость нужна транзитивно (`openai`), перенос меняет состав runtime-зависимостей.
- Возврат `--strict` в CI и правка спецификации `continuous-integration` (требование «`openspec validate --specs --strict`» расходится с фактическим workflow без `--strict`) — это предсуществующее расхождение, учтённое в `backlog.md` P2.13; в этом change'а оно только фиксируется как известное.
- Любые изменения продуктового поведения, API и зависимостей.

## Capabilities

### New Capabilities
- `agent-governance`: правила работы агента и разработчика в проекте — приватность пользовательских данных (`input/`, `.env`), русский язык ответов, дисциплина линтера и тестов, порядок работы с OpenSpec и разрешений на git-операции, достоверность документации проекта, нормы стиля кода.

### Modified Capabilities
- (нет — требования существующих capabilities `change-lifecycle`, `configuration`, `continuous-integration`, `pdf-hybrid-comparison` не меняются; новая редакция `AGENTS.md` им не противоречит, а фиксируемое расхождение по `--strict` вынесено в non-goals)

## Impact

- **Документация:** `AGENTS.md` (правила проекта), `README.md` (пользовательская документация), `backlog.md` (журнал задач).
- **Спецификации:** новая capability `agent-governance` → `openspec/specs/agent-governance/spec.md` при архивировании.
- **Тесты:** новый файл `tests/test_docs_consistency.py` (без изменения продуктового кода и существующих тестов).
- **Продуктовый код:** не затрагивается — правки касаются только документации, спецификаций и одного тестового файла.
- **API, зависимости, рантайм:** без изменений.
- **CI:** без изменений; фактическая команда `openspec validate --specs` (без `--strict`) отражается в `README.md` как есть.
