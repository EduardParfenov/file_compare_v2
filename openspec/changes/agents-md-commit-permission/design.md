## Context

В текущем `AGENTS.md` (раздел 14 «Правила взаимодействия с агентом») пункт 1 запрещает агенту autonomously делать `git commit` / `git push`. Любые изменения в Git выполняются только пользователем после явного подтверждения каждого шага. Это безопасно, но требует ручного вмешательства пользователя после каждого согласованного изменения.

## Goals / Non-Goals

**Goals:**
- Заменить полный запрет на коммиты/пуши агентом на правило «коммиты и пуши только с явного разрешения пользователя».
- Агент может подготовить изменения (изменить файлы, проиндексировать их), но фактический `git commit`, создание ветки и `git push` выполняются только после отдельного подтверждения пользователя на каждый шаг.

**Non-Goals:**
- Изменение правил создания OpenSpec-артефактов (пункт 2 раздела 14 остаётся без изменений).
- Изменение порядка переходов между шагами планирования (пункт 3 раздела 14 остаётся без изменений).
- Изменение запрета на прямые коммиты в `main` (раздел 13, пункт 2 остаётся без изменений).

## Decisions

**Явное разрешение на каждый шаг Git.**
- Решение: агент может готовить изменения (`git add`), но `git commit`, `git branch`, `git push` выполняются только после явного «да» пользователя на каждый конкретный шаг.
- Обоснование: сохраняет контроль пользователя над историей Git, но убирает необходимость в ручном выполнении коммита после каждого изменения.
- Альтернатива: оставить полный запрет (текущее поведение) — отвергнуто, так как замедляет разработку без 추가тельной пользы.

**Запрет на коммиты в `main` сохраняется.**
- Решение: раздел 13 (прямые коммиты в `main` запрещены) остаётся без изменений.
- Обоснование: защита ветки `main` через pull-request — отдельное правило, не зависящее от того, кто делает коммит.

## Risks / Trade-offs

- [Агент может забыть запросить разрешение перед коммитом] → пользователь видит uncommitted изменения и сам решает, фиксировать их или нет.
- [Несанкционированный push в чужие ветки] → запрет на `main` в разделе 13 и требуемое явное разрешение на каждый push снижают этот риск.

## Migration Plan

- Отредактировать `AGENTS.md` раздел 14, пункт 1: заменить формулировку полного запрета на правило «коммит и push только с явного разрешения пользователя».
- Проверить, что остальные пункты раздела 14 и раздел 13 остаются без изменений.
